# Independent architecture and documentation review

## Executive Assessment

**PASS WITH WARNINGS.** The baseline describes the main design accurately enough to guide development. WinMuxX owns virtual workspaces and their organization. macOS and other applications control the actual windows. The main exceptions concern gesture lifetime, recovery instructions, and claims about existing test coverage. Read the source before relying on the baseline for changes in those areas.

The review compared the original baseline through `83d56e77` with editorial commit `a41d9823`. It traced ownership, layout, recovery, and native event paths against Swift source and existing tests. The checkout had unrelated Scrolling changes during the review. The gesture findings concern the committed receiver, coordinator, and workspace state. The focused Swift run passed 118 model and command tests across arrangement normalization, overlapping runtime events, restart, display navigation, and Dock swipe tracking. It ran in the working checkout. No real desktop validation was performed. Local links and anchors resolved. Diagram text matched the previous revision.

## Verified Strengths

1. **Workspace selection and relocation have distinct rules.** Selection uses existing ownership, including for a hidden workspace. An explicit move checks configured assignment, fills the source display when necessary, and prevents old recovery state from undoing the move. Viewport assignment guards against showing one workspace on two displays. Tests exercise hidden selection, forced assignment, source fallback, and reconnection. [Assignment policy](../../Sources/AppBundle/tree/WorkspaceMonitorAssignment.swift#L29), [navigation tests](../../Sources/AppBundleTests/command/MonitorWorkspaceNavigationTest.swift)
2. **The shared tree and separate layout state match the implementation.** Dwindle can calculate nested splits, Tabbed tracks groups and selected tabs, and Scrolling tracks the strip offset separately from workspace membership. The transition can wrap the root and synchronize Tabbed groups. Existing tests cover selected paths back to Dwindle and verify saved Tabbed selection. Preserve these distinctions when changing a layout. [Traversal](../../Sources/AppBundle/layout/layoutRecursive.swift), [transition](../../Sources/AppBundle/tree/MasterLayout.swift#L8), [round-trip tests](../../Sources/AppBundleTests/tree/NormalizeContainersArrangedTest.swift#L52), [Tabbed tests](../../Sources/AppBundleTests/command/WorkspaceTabbedArrangementTest.swift#L294)
3. **Recovery and event handling account for external uncertainty.** Restart matching uses process launch evidence for direct ID matches and checks uniqueness when matching metadata. Activation reconciliation checks the workspace selection generation. Frame recovery limits repeated writes when another app keeps moving a window. These safeguards have specific scopes that future changes should preserve. [Identity matcher](../../Sources/AppBundle/tree/frozen/RestartWindowIdentity.swift#L55), [refresh](../../Sources/AppBundle/layout/refresh.swift#L43), [frame recovery](../../Sources/AppBundle/runtime/FrameRecovery.swift), [restart tests](../../Sources/AppBundleTests/tree/RestartWorkspaceTest.swift#L419)

## Documentation Quality

The editorial pass improved the Product Manager overview, split compound sentences, and turned the agent workflow into a numbered procedure. The glossary clarifies that a display viewport tracks a visible workspace and a Scrolling viewport describes a visible portion of the strip. Comparison with the prior revision found no removed source links, changed diagram text, altered invariant rows, or change to the body of the approval requirement. The review found no material change to architectural decisions or evidence labels. The gesture ambiguity and recovery gap predate the editorial pass. [Glossary](DOMAIN.md#glossary), [Product Manager review](PM_REVIEW.md), [governance](GOVERNANCE.md)

The result follows the practical writing goals unevenly. The opening pages are accessible. Several technical tables still combine ownership, input, side effects, and evidence in one cell. The generic viewport definition says “a context that selects or shows part of something,” which adds little before the two precise terms. Introduce Accessibility (AX) and Architecture Decision Record (ADR) at first use in their relevant pages. Keep terms such as process launch identity, refresh generation, and Scrolling offset where they make the behavior precise. This is a pragmatic review of readability, with no formal compliance score. ## Recommended Improvements

1. Correct the gesture and recovery descriptions first. They describe when the program may act on a window and when the user must act. Add direct links to the receiver and menu entry.
2. Update the coverage inventory before adding tests. Use the existing round-trip and held-refresh fixtures as starting points. Target the missing gesture lifetime case and additional membership, nested-group, and focus assertions.
3. Put the display assignment exception next to the selection rule. Clarify policy precedence, separate proposed invariants from adopted requirements, and qualify claims with the scope that the code and tests establish.
4. Keep the glossary definitions concrete. Split dense event or state table cells only where a reader needs to distinguish a trigger, owner, or outcome. Extend the existing link check when practical.

## Product Manager Decision Brief

1. **Can I trust the documentation?** Yes, for the main design and the approval process. Check the updated guidance or the linked code before changing gestures, restart recovery, or display assignment.
2. **What are the most important risks?** A horizontal swipe may still affect its original workspace after an intervening change. The recovery description can create the wrong expectation about which positions come back. A future agent could duplicate existing tests or treat a proposed rule as an approved requirement.
3. **What should we correct first?** Explain exactly when gesture callbacks are accepted and when each recovery path runs. Update the test inventory before approving more broad coverage work.
4. **Which changes require my approval?** The review can be addressed through factual documentation and tests of existing behavior. A change to what a swipe does during a workspace or display change, a significant event-processing change, or a saved-state change follows the architecture approval process. The product question already identified is whether the last Scrolling position should survive restart when the workspace was using another arrangement at shutdown. No decision is needed to complete these corrections. [Product Manager review](PM_REVIEW.md), [governance](GOVERNANCE.md)
5. **What should we leave alone?** Preserve selection versus explicit movement, cautious matching of saved windows, separate recovery stores, and separate layout state on the shared tree. This review found no reason to redesign those parts.

## Final Verdict

**PASS WITH WARNINGS.** The source and named tests support the central architecture. The editorial changes generally preserve its meaning. Directed corrections to gesture lifetime, recovery triggers, and test traceability would make the baseline safer to use as an engineering contract. Treat the gesture timing consequence as a test hypothesis until reproduced.
